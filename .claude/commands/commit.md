# Commit

Generate a clear, concise commit message for the currently staged changes and commit them.

## Process

1. Run `git status` to check for staged changes. If nothing is staged, inform the user and stop.
2. Run `git diff --cached` to analyze the staged changes.
3. Run `git log --oneline -5` to understand recent commit style and context.
4. Generate a commit message following the format below.
5. Run `git commit -m "<message>"` immediately (do NOT ask for confirmation).

## Commit Message Format

```
<type>: <short description>

<optional body>
```

### Types
- `feat`: New feature
- `fix`: Bug fix
- `docs`: Documentation changes
- `style`: Formatting, missing semicolons, etc. (no code change)
- `refactor`: Code restructuring without changing behavior
- `perf`: Performance improvement
- `test`: Adding or updating tests
- `chore`: Build process, dependencies, tooling

### Rules
- Use imperative mood ("add" not "added")
- First line under 72 characters
- Body is optional — include only if the change needs explanation
- Be specific but concise
- Do NOT add "Generated by AI" or any attribution
- Do NOT add co author or any other text like that.
